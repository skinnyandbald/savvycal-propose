# Migrate Supabase Auth to Better Auth + Neon

**Date:** 2026-03-30
**Status:** Approved
**Scope:** Replace Supabase Auth with Better Auth + Drizzle + Neon Postgres

## Problem

The project uses Supabase solely for Google OAuth on a single-user app. This costs $10/mo and requires a GitHub Actions cron job to prevent free-tier pausing. Supabase is also deprecating anon key access to `/rest/v1/` on April 8th, which breaks that cron job.

## Solution

Replace Supabase Auth with Better Auth + Drizzle ORM + Neon Postgres (free tier, already connected to Vercel project via Marketplace). Delete the keep-alive workflow.

## Auth Flow

```
Login page → "Sign in with Google" → Google OAuth
→ Better Auth callback (/api/auth/callback/google)
→ Creates session in Neon Postgres
→ Middleware checks session cookie → redirect to /login if absent
→ Page-level check verifies ALLOWED_EMAIL (defense-in-depth)
```

The user-facing flow is unchanged. Sign in with Google, land on /propose if authorized.

## Implementation Order

Execute in this sequence to avoid broken builds:

1. **Environment setup** — Add `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` to Vercel. Run `vercel env pull` to sync `DATABASE_URL` + new vars locally. 2. **Google Cloud Console** — Add new redirect URI (`/api/auth/callback/google`) alongside existing Supabase URI. Do NOT remove the Supabase URI yet. Also add `http://localhost:3000/api/auth/callback/google` for local dev.
3. **Install packages** — Add `better-auth`, `drizzle-orm`, `drizzle-kit`, `@neondatabase/serverless`. Keep Supabase packages temporarily.
4. **Create `lib/auth/index.ts`** — Better Auth server config (required before schema generation).
5. **Create `lib/db/index.ts`** — Neon connection + Drizzle instance.
6. **Generate schema** — Run `npx @better-auth/cli generate` (reads auth config to produce correct schema). Commit the generated file.
7. **Run `drizzle-kit push`** — Create auth tables in Neon. Verify tables exist (run `drizzle-kit studio` or check Neon dashboard).
8. **Create `lib/auth/client.ts`** — Browser auth client.
9. **Create catch-all route** — `app/api/auth/[...all]/route.ts`.
10. **Modify middleware** — Replace Supabase session check with `getSessionCookie()`. No `/login` redirect logic in middleware.
11. **Modify components** — `LoginButton.tsx`, `SignOutButton.tsx`.
12. **Modify pages/routes** — `login/page.tsx`, `page.tsx`, `propose/page.tsx`, `api/slots/route.ts`.
13. **Delete Supabase files** — `lib/supabase/*`, `app/auth/callback/route.ts`.
14. **Remove Supabase packages** — `@supabase/ssr`, `@supabase/supabase-js`.
15. **Delete keep-alive workflow** — `.github/workflows/keep-supabase-alive.yml`.
16. **Verify in production** — Run full auth checklist (see Testing section).
17. **Post-migration cleanup** — After 1 week stable: remove Supabase URI from Google Console, remove Supabase env vars from Vercel.

## Middleware Strategy

Use edge-compatible `getSessionCookie()` — NOT `auth.api.getSession()`. Middleware only gates presence of cookie. No email checking (can't hit DB from Edge). No `/login` redirect logic (causes redirect loops for unauthorized users).

```typescript
import { NextRequest, NextResponse } from "next/server";
import { getSessionCookie } from "better-auth/cookies";

export async function middleware(request: NextRequest) {
  const sessionCookie = getSessionCookie(request);

  if (!sessionCookie) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/propose/:path*", "/api/slots/:path*"],
};
```

`/` and `/login` are NOT in the matcher. `page.tsx` handles `/` logic. `login/page.tsx` handles redirecting already-authorized users away from login.

## ALLOWED_EMAIL Enforcement (Defense-in-Depth)

**Middleware:** Cookie presence only. No email check.

**`login/page.tsx` (server component):**
```typescript
import { headers } from "next/headers";
import { auth } from "@/lib/auth";

const session = await auth.api.getSession({ headers: await headers() });
const allowedEmail = process.env.ALLOWED_EMAIL?.toLowerCase();

// Redirect authorized users away from login
if (session?.user.email?.toLowerCase() === allowedEmail) {
  redirect("/propose");
}

// Show sign-out button when unauthorized session exists
const isUnauthorized = (await searchParams).error === "unauthorized";
// Render: error message + <SignOutButton /> if isUnauthorized
```

**`page.tsx` (root `/`):**
```typescript
const session = await auth.api.getSession({ headers: await headers() });
const allowedEmail = process.env.ALLOWED_EMAIL?.toLowerCase();

if (!session) redirect("/login");
if (session.user.email?.toLowerCase() !== allowedEmail) redirect("/login?error=unauthorized");
redirect("/propose");
```

**`propose/page.tsx`:**
```typescript
const session = await auth.api.getSession({ headers: await headers() });
if (!session || session.user.email?.toLowerCase() !== process.env.ALLOWED_EMAIL?.toLowerCase()) {
  redirect("/login?error=unauthorized");
}
```

**`api/slots/route.ts`:**
```typescript
const session = await auth.api.getSession({ headers: request.headers });
if (!session) return new Response("Unauthorized", { status: 401 });
if (session.user.email?.toLowerCase() !== process.env.ALLOWED_EMAIL?.toLowerCase()) {
  return new Response("Forbidden", { status: 403 });
}
```

**Unauthorized user flow:** User signs in with wrong Google account → Better Auth creates a session → page-level checks reject them → redirected to `/login?error=unauthorized` → sees "Access denied" error + `<SignOutButton>` to clear the session cookie.

## Database Schema

Generated by `npx @better-auth/cli generate`. Do NOT hand-write. Four tables:

- **user** — id, name, email, emailVerified, image, createdAt, updatedAt
- **session** — id, userId, token, expiresAt, ipAddress, userAgent, createdAt, updatedAt
- **account** — id, userId, accountId, providerId, accessToken, refreshToken, idToken, accessTokenExpiresAt, refreshTokenExpiresAt, scope, password, createdAt, updatedAt
- **verification** — id, identifier, value, expiresAt, createdAt, updatedAt (required by Better Auth even for Google-only OAuth)

## Error Handling

- Wrong email → page/route checks redirect to `/login?error=unauthorized`. Login page displays "Access denied." + `<SignOutButton>`.
- Auth failure → Better Auth redirects to `/login?error=auth` via `errorCallbackURL`. Login page displays "Authentication failed."
- Unauthenticated access to protected routes → middleware redirects to `/login`.

## Testing

Production verification checklist (run after deploy, before removing Supabase):

1. OAuth starts on primary domain — sign in redirects to Google, returns to `/api/auth/callback/google`
2. Allowed email → session cookie set → lands on `/propose`
3. Refresh `/propose` → still authenticated (cookie persists)
4. Sign out → cookie cleared → `/propose` redirects to `/login`
5. Wrong Google account → lands on `/login?error=unauthorized` with sign-out button
6. Unauthenticated direct URL to `/propose` → redirected to `/login`
7. `GET /api/slots` with no session → 401
8. `GET /api/slots` with wrong-email session → 403
9. Root `/` unauthenticated → `/login`
10. Root `/` authenticated with allowed email → `/propose`
11. OAuth consent denied → `/login?error=auth`
